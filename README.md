## Часть 1. Решатель FVS

**Идея** 
Многократно удаляются все вершины с in- или out-степенью 0 (Ядровизация: они не лежат ни на одном цикле). 
Пока есть живые вершины, по исходящим дугам из тяжёлой вершины (максимум `in·out`) находится цикл, на нём в ответ убирается вершина с максимальным весом `in+out` (небольшая доля случайных выборов), затем ядро пересчитывается. После жадной конструкции выполняется локальное улучшение: вершина возвращается из ответа, если граф без неё остаётся ацикличным. Всё повторяется много раз со случайными рестартами; запоминается лучший
допустимый ответ. По SIGTERM программа выводит лучшее найденное множество.

**Запуск:**

```bash
# читает граф из stdin, ответ (номера вершин по одному в строке) — в stdout
python3 solution_fvs.py < hard_graph.gr > out.txt
```

## Часть 2. «Трудный» граф

**Идея** Берётся ациклический остовный путь `a_1 → … → a_n` и `r` «разрезов» на нём.
Все прямые рёбра расположены внутри сегментов между разрезами, поэтому **перейти границу вперёд
можно только через вершину-разрез**, а любое обратное ребро (хорда) перекрывает хотя бы одну
границу и вместе с прямым путём образует цикл, обязательно проходящий через разрез. 
Захардкодили в генераторе число разрезов = 60.
Таким образом минимальное FVS равно `r` (60): удаление разрезов уничтожает все циклы. Жадные эвристики же разрушают «декоративные» хорды по одной и удаляют ~20 раз больше вершин, что и делает граф трудным.

**Граф** — `hard_graph.gr` (n=200000, m=945000, без петель и кратных дуг, есть циклы).
**Ответ аналитический (по построению)** — `hard_graph_analytic.ans`: Ответ полученный скриптом - генератором графа. 60 вершин-разрезов; 
**Ответ алгоритма** — `hard_graph_decision.ans`: Ответ полученный алгоритмом Части 1 задания, содержит 1358 вершин;
